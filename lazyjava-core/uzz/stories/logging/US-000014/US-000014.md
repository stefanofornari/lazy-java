## logging/US-000014 — Use System Properties and Environment Variables in the Log File Pattern

### User Story

```
AS A Developer
I WANT to refer to system properties and environment variables in the log file pattern
SO THAT I can place the log file wherever my deployment or launcher says without changing the properties file
```

#### Technical Context & Constraints
* **Target System**: JVM library module `lazyjava-core`, classpath.
* **Toolchain / Rules**: Java 11 + Maven; JUnit 5 + AssertJ; `java.util.logging` only; code in `lazyjava-core` (`ste.lazyjava.logging`). Reference docs per `logging/scope.md`.

#### Notes
1. `${env.NAME}` is the environment variable `NAME`; any other `${name}` is a system property.
2. A token that cannot be resolved (unknown name, unset environment variable, system folder token without `application`, unterminated `${`) never stops the logging: the text of the token is kept in the pattern, so that the file name shows what is wrong, and a warning is reported once per token. The warning is published as the first record to the handler itself (the file) and written on `System.err`; logging it through a `Logger` is not possible while the `LogManager` is still loading its handlers. Decision of 2026-11-09, replacing the first design that threw an exception, so that missing logs are noticed.
3. Same value safety as for the system folders (`\` to `/`, `%` escaped).

### Acceptance Criteria

```gherkin
Scenario: System property expanded
  Given the system property `lazytest.dir` and the pattern `${lazytest.dir}/p.%g.log`
  When  the handler is created
  Then  the file is created in that folder

Scenario: Environment variable expanded
  Given the environment variable PATH
  When  the pattern text `${env.PATH}` is expanded
  Then  the result is the value of PATH, made safe for a pattern

Scenario: Unknown token
  Given the pattern `<folder>/${nothing.here}/app.%g.log`
  When  the handler is created
  Then  the token stays as it is in the path, the log file is written there, and a warning naming `${nothing.here}` is the first record of the file and is also written on System.err

Scenario: Unset environment variable
  Given the pattern `<folder>/${env.LAZYTEST_SURELY_UNSET}/app.%g.log`
  When  the handler is created
  Then  the token stays as it is and a warning names it

Scenario: Warning only once
  Given a pattern that uses the same unresolvable token twice and a resolvable one
  When  the handler is created
  Then  the resolvable token is expanded, the unresolvable one stays, and it is reported once

Scenario: Value with a percent sign
  Given a property whose value contains `%`
  When  the handler is created
  Then  the `%` is taken literally
```
