## logging/US-000013 — Place the Log File in the System Folders of the Application

### User Story

```
AS A Developer
I WANT to use ${dataDir}, ${cacheDir} and ${configDir} in the log file pattern
SO THAT the log goes where the operating system expects the data of my application, on every platform
```

#### Technical Context & Constraints
* **Target System**: JVM library module `lazyjava-core`, classpath.
* **Toolchain / Rules**: Java 11 + Maven; JUnit 5 + AssertJ; `java.util.logging` only; code in `lazyjava-core` (`ste.lazyjava.logging`). Reference docs per `logging/scope.md`.

#### Notes
1. Tokens are expanded before the file is opened, using [directories-jvm](https://codeberg.org/dirs/directories-jvm) (`dev.dirs:directories` 26, added to `lazyjava-core`): `ProjectDirectories.from(qualifier, organization, application)`; `dataDir` is `dataLocalDir`, plus `cacheDir`, `configDir`.
2. `application` is required (`ste.lazyjava.logging.FileLogHandler.application`) to resolve the system folder tokens; without it the tokens are left as they are and a warning is reported (see US-000014); `qualifier` and `organization` default to empty. `${application}` expands to the application name.
3. Default pattern `${dataDir}/logs/${application}.%g.log`.
4. Expanded values are safe in a pattern: `\` becomes `/`, `%` is escaped. The literal `%g`, `%u`, `%h`, `%t` keep their JDK meaning.
5. Not tested against real Windows/macOS folders here; the tests compare with `ProjectDirectories` itself.

### Acceptance Criteria

```gherkin
Scenario: dataDir expanded to the system data folder
  Given application `lazytest` and the pattern `${dataDir}/x.%g.log`
  When  the handler is created
  Then  the file is created in the data folder of `lazytest` as given by directories-jvm

Scenario: Default pattern
  Given an application name and no pattern
  When  the handler is created
  Then  the file `<dataDir>/logs/<application>.0.log` is used

Scenario: Application name missing
  Given a pattern with `${dataDir}` and no application
  When  the handler is created
  Then  the token is left as is in the pattern, so the log is still written (with `${dataDir}` visible in its path), and a warning saying that the application is not set is reported once
```
