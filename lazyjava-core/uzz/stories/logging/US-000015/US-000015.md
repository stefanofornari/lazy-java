## logging/US-000015 — Report a Log File Failure Through JUL and Keep Logging Elsewhere

### User Story

```
AS A Developer
I WANT to an unusable log file to be reported by the logging framework without breaking the other handlers
SO THAT the application still starts and keeps logging to the console when the file cannot be used
```

#### Technical Context & Constraints
* **Target System**: JVM library module `lazyjava-core`, classpath.
* **Toolchain / Rules**: Java 11 + Maven; JUnit 5 + AssertJ; `java.util.logging` only; code in `lazyjava-core` (`ste.lazyjava.logging`). Reference docs per `logging/scope.md`.

#### Notes
1. The constructor throws `IOException` (e.g. folder not writable, unknown token, missing application). `LogManager` catches it when loading `handlers`, prints the error to `System.err` and continues with the remaining handlers.
2. No fallback location and no silent failure (see `logging/scope.md`).

### Acceptance Criteria

```gherkin
Scenario: File cannot be created
  Given `handlers = java.util.logging.ConsoleHandler, ste.lazyjava.logging.FileLogHandler` and a pattern in a folder that cannot be created
  When  the log manager reads the configuration and a message is logged
  Then  the console handler still writes the message and the failure is reported with the reason

Scenario: Constructor error
  Given a pattern that cannot be resolved
  When  the handler is created directly
  Then  an IOException is thrown
```
