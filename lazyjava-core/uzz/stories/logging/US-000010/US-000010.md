## logging/US-000010 — Configure a File Log Handler from logging.properties

### User Story

```
AS A Developer
I WANT to configure a file log handler entirely from the standard logging.properties
SO THAT I can set up file logging without writing any configuration code
```

#### Dependencies

#### Technical Context & Constraints
* **Target System**: JVM library module `lazyjava-core`, classpath.
* **Toolchain / Rules**: Java 11 + Maven; JUnit 5 + AssertJ; `java.util.logging` only; code in `lazyjava-core` (`ste.lazyjava.logging`). Reference docs per `logging/scope.md`.

#### Notes
1. Public class `ste.lazyjava.logging.FileLogHandler` extends `java.util.logging.FileHandler` and has a public no-argument constructor, as the `LogManager` requires to load it from `handlers`.
2. Settings are read from the `LogManager` under `ste.lazyjava.logging.FileLogHandler.`: `pattern`, `level`, `filter`, `formatter`, `encoding`, `append` (default true). The JDK `FileHandler` reads level, filter, formatter and encoding from the same class-name namespace.
3. Without `formatter`, `SimpleFormatter` is used (the JDK default would be XML).
4. A spike exists as `ste.lazyjava.logging.ConfigurableFileHandler`; this story renames/adjusts it to `FileLogHandler` (tests first).

### Acceptance Criteria

```gherkin
Scenario: Handler loaded through the handlers property
  Given a logging.properties with `handlers = ste.lazyjava.logging.FileLogHandler` and a `pattern` pointing to a writable file
  When  a message is logged and the log manager is reset
  Then  the message is in the file, written with SimpleFormatter

Scenario: Settings read from the handler's own namespace
  Given level WARNING and a formatter configured under `ste.lazyjava.logging.FileLogHandler.`
  When  the handler is created
  Then  its level is WARNING and its formatter is the configured one

Scenario: Plain FileHandler settings are not picked up
  Given settings only under `java.util.logging.FileHandler.`
  When  the handler is created
  Then  they are ignored and the defaults of this handler apply
```
