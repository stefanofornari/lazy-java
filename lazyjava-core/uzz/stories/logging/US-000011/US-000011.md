## logging/US-000011 — Keep the Log File Size Bounded by Default

### User Story

```
AS A Developer
I WANT to the log file to be rolled with a cap, also when I do not configure one
SO THAT the log never grows indefinitely and fills the disk
```

#### Technical Context & Constraints
* **Target System**: JVM library module `lazyjava-core`, classpath.
* **Toolchain / Rules**: Java 11 + Maven; JUnit 5 + AssertJ; `java.util.logging` only; code in `lazyjava-core` (`ste.lazyjava.logging`). Reference docs per `logging/scope.md`.

#### Notes
1. `limit` (bytes, default 1 000 000) and `count` (files, default 3) are read from the handler's namespace; invalid values fall back to the defaults.
2. Rotation is the one of `FileHandler`, with `%g` in the pattern for the generation number.
3. The cap is the point of the story: it must hold with no `limit`/`count` in the properties.

### Acceptance Criteria

```gherkin
Scenario: Configured cap is respected
  Given limit 2000 and count 2
  When  far more than 2000 bytes are logged
  Then  there are at most 2 log files

Scenario: Default cap applies when nothing is configured
  Given a pattern and no limit or count
  When  the handler is created
  Then  it rotates at 1 000 000 bytes and keeps 3 files

Scenario: Invalid values fall back to the defaults
  Given limit and count that are not numbers
  When  the handler is created
  Then  the default limit and count apply
```
