## core/docs/US-000007 — Publish LazyJava Documentation via GitHub Pages

### User Story

```
AS A Developer
I WANT LazyJava module and usage documentation published through the parent project’s GitHub Pages
SO THAT I can understand what LazyJava provides, how modules fit together, and how to use the library from a single discoverable site
```

#### Status
WIP

#### Dependencies
- None

#### Technical Context & Constraints
* **Target System**: Parent repository GitHub Pages documentation (`docs/`) and repository `README.md`.
* **Toolchain / Rules**: Jekyll site in `docs/` (native GitHub Pages build) via repository Settings → Pages → Deploy from a branch, source branch + `/docs` folder. No GitHub Actions workflow required. Keep `README.md` concise and authoritative for quick project context. KB/story structure follows `uzz/skills/kb` and `uzz/skills/story`.
* **Phase**: Documentation implementation in progress (site scaffold created; publication depends on GitHub Pages repository settings).

#### Notes
1. Extracted usage content from parent `README.md` into `docs/getting-started.md`.
2. Added `docs/index.md`, `docs/modules.md`, `docs/requirements.md`, and `docs/_config.yml`.
3. README now provides concise context and links to GitHub Pages pages. Compatibility details are documented in `docs/requirements.md` and tracked by `core/docs/US-000009`.

### Acceptance Criteria

```gherkin
Scenario: Usage documentation is available on GitHub Pages
  Given the LazyJava parent repository with GitHub Pages content
  When a developer looks for library usage guidance
  Then the GitHub Pages site contains the extracted usage information previously maintained in README (setup, plugin wiring, annotations, validation, requirements)

Scenario: README points to detailed documentation
  Given the repository README
  When a developer reads the project overview
  Then README provides concise project context and links to GitHub Pages for detailed usage and module documentation
```
