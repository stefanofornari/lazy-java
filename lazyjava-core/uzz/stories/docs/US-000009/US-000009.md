## core/docs/US-000009 — Clarify Java Version and Toolchain Compatibility in GitHub Pages and README

### User Story

```
AS A Developer
I WANT Java/toolchain requirements to be consistent and clearly explained in GitHub Pages and README
SO THAT I receive consistent information about Java compatibility
```

#### Status
WIP

#### Dependencies
- core/docs/US-000007

#### Technical Context & Constraints
* **Target System**: GitHub Pages documentation (`docs/requirements.md`), repository `README.md`, and module/repository build metadata as reference.
* **Toolchain / Rules**: Parent POM and README indicate Java 21/Maven 3.6+ project baseline; `lazyjava-core/pom.xml` currently compiles with Java 11 source/target. Documentation must make the intended boundary explicit.
* **Phase**: Documentation clarification in progress.

#### Notes
1. Added initial compatibility explanation in `docs/requirements.md` distinguishing project-level requirements from `lazyjava-core` module compiler settings.
2. README now links to the compatibility page; it no longer repeats the potentially ambiguous requirement as the sole source.
3. Follow-up validation may be needed to confirm intended supported Java versions before marking DONE.

### Acceptance Criteria

```gherkin
Scenario: Compatibility guidance is unambiguous
  Given GitHub Pages docs, README, and project build configuration
  When a developer checks Java requirements
  Then they can determine supported Java versions for lazyjava-core and for LazyJava overall without contradictory statements

Scenario: Extracted usage docs include accurate requirements
  Given usage content extracted from README into GitHub Pages
  When compatibility guidance is published
  Then the requirements section in GitHub Pages and README accurately reflects intended compile/runtime requirements or clearly explains any intentional differences
```
